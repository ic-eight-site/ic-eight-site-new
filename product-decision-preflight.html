Product Decision · Preflight

Before you test the product, define what would count.

Product Decision Preflight starts with what a company publicly promises, then turns that promise into a focused question for actual use. It keeps the claim, the verification hypothesis, and what remains unknown visibly separate.

Saved, static AI-generated examples. Viewing this page does not retrieve a website or call a model or API. These are public-information preflights, not actual-use Product Value Evaluations or completed Product Decision Reviews.

How to read the sample

A promise is a starting point. The test still has to be designed.

Each example preserves the evidence chain from an official public page to a question that can later be answered through controlled product use. Nothing in the preflight is presented as an observed product result.

Verification hypothesis · not yet tested

Can pasted or imported text be turned into a useful visual for sharing?

Proposed user goal
If used for this task: turn pasted or imported text into a visual for sharing.
First meaningful success
A visual is generated from a pasted or imported text sample and is available to review.
Reasoning from the public evidence
Napkin says it works directly from text and turns text into visuals, while describing sharing ideas as quick and effective. Generating and reviewing a visual is an observable first-use proxy; whether it is useful or effective for an audience remains unverified.

What actual use would check

  1. Paste a short, hypothetical outline into Napkin.
  2. Generate a visual from that text.
  3. Review whether the generated visual represents the outline clearly enough to share.

Verification hypothesis · not yet tested

Can a generated visual be exported in a format needed for later use?

Proposed user goal
If used for this task: create a visual from text and export it for use in another format.
First meaningful success
A generated visual is exported in one of the stated formats, such as PNG or PDF.
Reasoning from the public evidence
The company says created visuals can be used anywhere and names four export formats. Producing and opening an export is observable; suitability for a particular downstream workflow is unverified.

What actual use would check

  1. Generate a visual from a short, hypothetical text sample.
  2. Choose one stated export format, such as PNG, PDF, PPT, or SVG.
  3. Confirm that an exported file is produced and can be opened in an appropriate viewer.

Public-information preflight

What remains unverified in this preflight

  • Actual-use performance is unverified: the supplied passages do not show whether generated visuals accurately represent text or make sharing quick and effective. If used for turning text into shareable visuals, this determines whether the stated promise is achieved in practice.
  • Export fidelity and downstream compatibility are unverified: the passages name PPT, PNG, PDF, and SVG but provide no examples of exported output. If used for exporting a generated visual, this matters to the promise that visuals can be used anywhere.
  • The extraction is bounded and omits 84 passages, including the answer text for “What is Napkin AI?” and pricing details. This limits evaluation of the sourced promises and intended tasks; it does not establish a missing feature or defect.

Sources and evidence boundary

Only homepage passages entered the model context. The pricing page was accessible and retrieved, but pricing-page text was not supplied to this analysis. The capture itself is bounded; missing details here do not establish that a feature, policy, or capability is absent.

Verification hypothesis · not yet tested

Can Parseur extract the needed document information into structured data and deliver it to the intended app, spreadsheet, or database?

Proposed user goal
If used for this task, automate extraction of information from PDFs, scans, emails, or images and use the resulting structured data in an existing application, spreadsheet, or database.
First meaningful success
A document’s selected information is represented as structured data and delivered to a chosen existing destination for use in that workflow.
Reasoning from the public evidence
The company says its extraction converts several document types into structured data and delivers it to tools teams already use; the proposed result is the observable output needed to use that data downstream.

What actual use would check

  1. Review public product documentation or demonstrations for the relevant input type and intended destination.
  2. Confirm publicly documented field-extraction and delivery options match the specific workflow before relying on the automation.
  3. If later evaluated in a controlled environment, use a hypothetical representative document and inspect whether the resulting structured record is usable in the intended destination.

Company promise · paraphrase

Parseur promises to automate document-data copying work, claiming fewer errors and no extra hires.

See the exact public evidence

“manually copy data from invoices, emails, and documents into their tools”

“does it automatically, with fewer errors and zero extra hires”

Document extraction capability

“automate text extraction from PDFs, emails, and other documents.”

Feature source E1 · parseur.com ↗

Verification hypothesis · not yet tested

Does the proposed extraction-and-delivery workflow replace the relevant manual copy-paste step with usable structured data?

Proposed user goal
If used for this task, reduce manual copying of information from invoices, emails, and documents into existing tools.
First meaningful success
Information that would otherwise be copied manually is available as a structured record for use in the destination workflow.
Reasoning from the public evidence
The site positions the product as an alternative to manually copying data from common business documents, while its stated automation claim is distinct from demonstrated error or staffing outcomes.

What actual use would check

  1. Compare the publicly described input types and destination options with the manual copy-paste step being considered.
  2. Identify the exact fields that must be present in the structured output for the downstream task.
  3. Treat claims about fewer errors and staffing impact as company claims until later, controlled evaluation establishes results for the specific workflow.

Public-information preflight

What remains unverified in this preflight

  • Actual extraction accuracy, delivery reliability, and usefulness for a particular document type, fields, and destination are not demonstrated in the supplied passages. If used for the proposed extraction task, these determine whether the structured result can replace manual copying.
  • The supplied passages do not identify supported applications, spreadsheets, databases, field configurations, or API behavior. If used for the proposed delivery task, compatibility with the intended destination cannot yet be determined.
  • The supplied passages do not include privacy and compliance implementation details, certifications, data handling, or applicable terms. If documents are sensitive, these details matter when evaluating the company’s privacy promise.
  • The source capture omits 120 of 134 available passages and page completeness is unknown. Additional public details relevant to the stated automation promises may be outside this bounded evidence.
