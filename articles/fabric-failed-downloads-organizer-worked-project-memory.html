Diagnosis & Priority

Fabric Failed as a Downloads Organizer. It Worked as Project Memory.

Product Value Evaluation #045 · Published September 2026

Fabric did not solve the first job it was asked to solve.

In an earlier controlled test, the intended use was straightforward: point Fabric at a Downloads folder and let it organize a messy local file system. The natural path, Desktop file sync, was visibly Pro-gated. Fabric Free exposed manual upload instead. For that specific job, the user judged the Free plan to have no value.

That result remains valid.

The later evaluation did not reinterpret the failure or pretend manual upload was an acceptable substitute for automatic local-file organization. Instead, it changed the representative job.

The new question was narrower: once a small mixed-format project library had been deliberately created, could Fabric help recover what mattered from it?

Here the answer was materially better.

Plain Search remained inconsistent. But Fabric’s Assistant could reconcile superseded and current decisions, preserve unresolved issues, identify an exact duplicate pair, synthesize information across PDFs, Markdown and text notes, and SVGs, and link parts of its answer back to source items and specific PDF pages.

The strongest value therefore appeared not in automatic file organization and not in Search alone.

It appeared when Fabric behaved like project memory.

Key Findings

  • The earlier Downloads-organizer use case failed on Free because Desktop file sync was Pro-gated. Manual upload did not satisfy that job, and the later evaluation does not erase that result.
  • Fabric Free successfully accepted all 23 approved fictional files used in the later mixed-format tests through manual batch upload.
  • Plain Search produced mixed retrieval quality. It correctly ranked one SVG from a vague visual recollection, but it also returned a non-evidence navigation note for a wayfinding query, omitted the most explicit correction note from another visible result set, and failed to recover an exact duplicate pair together.
  • Assistant performed materially better on the controlled relational tasks. It reconciled old and approved decisions, recovered the newer low-battery decision, synthesized a solar requirement across several file types, and identified the exact duplicate pair.
  • P02 provided the strongest product-specific result. Before the approved replacement record was added to the P02 space, Assistant explicitly said the current plan could not yet be established. After newer files were added, the same conversation updated four superseded decisions while preserving unresolved installation, solar, calibration, alert, and review issues.
  • Source grounding was inspectable. One tested PDF citation opened the relevant PDF at page 2. But source presence was not exhaustive: the Wave 2 answer correctly stated the USD 4,800 ceiling without surfacing the visible budget CSV as corroborating evidence.

Evaluation Setup

The evaluation used two controlled simulated-persona tests on Fabric Free in Chrome from Brazil.

P01 tested imperfect-memory retrieval across a 15-file fictional corpus containing PDF, Markdown, TXT, CSV, JSON, and SVG files. The library intentionally included ambiguous names, overlapping claims, a superseded decision record, an exact duplicate, and a later operational update.

P02 tested growing project context in a separate space. Wave 1 contained four files describing an incomplete project state. Wave 2 added four newer files that changed several decisions while leaving other operational issues unresolved.

All files were fictional and purpose-built for the evaluation. No private user data or private ground truth was uploaded.

The v3 test intentionally replaced the earlier Downloads-triage job with a mixed-library retrieval and project-context job. This was not a retry designed to make the original result disappear. It tested a different representative use case after the first one had already exposed a genuine Free-plan boundary.

Audio and video were not tested. OCR over real scans, DOCX handling, native spreadsheet workflows, collaboration, long-term library drift, and larger corpus behavior also remain outside the evidence.

The Original Value Proposition Failed on Free

The first Fabric use case was appealing because it required almost no new behavior from the user.

The user already had a Downloads folder.

The hoped-for value was that Fabric would connect to that local file system, absorb the mess, and make it easier to recover what mattered later.

That path was not available for use on the tested Free account.

Desktop file sync was visibly Pro-gated. Free exposed manual upload.

That distinction matters because manual upload changes the job.

An automatic organizer reduces the cost of maintaining a knowledge system.

A manual library asks the user to decide what belongs in the system, upload it, and continue maintaining that boundary over time.

For someone whose original problem is “I do not want to manage these files,” that is not the same product value.

The user’s negative reaction to Free for the Downloads job was therefore not a misunderstanding that needed to be corrected. It described a real mismatch between the tested job and the available ingestion model.

Once the Library Existed, Search Was Not Enough

The later evaluation deliberately accepted manual ingestion as a condition and asked a different question: could Fabric help recover useful project knowledge after the library had been created?

Plain Search produced enough good results to show some semantic capability, but not enough consistency to become the trusted surface for the test.

A vague memory of an orange delay annotation worked well. Search ranked the correct IMG_1842.svg first with a relevant preview.

Other queries were weaker.

A vague recollection of a wayfinding study returned list.md, a navigation note that explicitly was not evidence for the underlying conclusion. A correction query placed a correct PDF first but omitted the most explicit short correction note from the visible results. A direct request for an exact duplicate pair did not return the pair together.

None of those individual misses proves that Fabric Search is broadly unreliable.

Together, they established a narrower boundary for this controlled corpus: semantic adjacency was not the same thing as evidence recovery.

That difference became important because Assistant behaved differently.

Assistant Behaved Like the Stronger Product Surface

When the same library was queried through Assistant, the results were materially better.

Assistant correctly reconciled four changes between draft and approved decisions. It resolved the newer low-battery decision over an older open question. It synthesized the Garden Three solar requirement across a PDF, Markdown file, SVG, and later update. It also identified meeting_8.md and copy_3.md as exact duplicates.

The important distinction was not simply that the Assistant produced longer answers.

It handled relationships among files.

That included chronology, authority, contradiction, duplication, and multi-source synthesis.

Those are precisely the questions that become difficult when a project folder contains more than one plausible answer.

Plain Search asked, in effect, “Which files are semantically close to this query?”

Assistant was more useful when the question became, “Given these files together, what should I currently believe?”

That is a more interesting product role.

P02 Showed What “Project Memory” Could Mean

The strongest evidence came from the two-wave project-context test.

Wave 1 deliberately contained an incomplete state: an initial brief, a superseded draft decision log, a Cedar proposal, and a field-layout SVG.

Assistant summarized the available project context but explicitly said the present plan could not yet be established because the approved replacement record was not yet present in the P02 space.

That restraint mattered.

The system did not flatten the draft into current truth merely because it was the most detailed document available.

Wave 2 then added four newer files: an approved decision log, a current update, a reference report, and a budget CSV.

In the same Assistant conversation, Fabric updated four material decisions:

30 sensors became 24.

60-minute readings became 30-minute readings.

Pine changed to Cedar after a rain-test failure.

The USD 5,500 ceiling changed to USD 4,800.

At the same time, Assistant preserved unresolved or active items rather than treating every newer file as a blanket resolution. It retained six uninstalled sensors, a two-day solar-kit delay, the eight-point A-17 calibration correction, alert implementation and validation, and the next review as still active.

This is the clearest value Fabric demonstrated.

The library did not merely contain old and new documents.

Assistant reconstructed a current project state from them.

This Was More Than Sorting by Modification Date

The value here should not be overstated.

A file system can already tell the user which file is newest.

That is not what P02 demonstrated.

The newer state was distributed across several files, and different decisions changed in different places. Some newer evidence superseded old decisions. Other issues remained unresolved. No single file was simply “the latest version of everything.”

Fabric’s Assistant combined those partial updates into one current-state answer.

That is where the project-memory framing becomes useful.

The product was not answering “Which file was modified last?”

It was answering “Across the evidence now in this space, what changed, what is currently true, and what is still open?”

For teams or individuals who already work through many evolving files, that can remove a real reconstruction task.

For users whose work is not file-centered, or whose project state already lives cleanly in one authoritative system, the value may be much smaller.

Grounding Made the Synthesis More Inspectable

Assistant also exposed source cards and links alongside its synthesis.

One source link attached to the A-17 calibration claim was opened during the audit and expanded the relevant PDF directly at page 2.

That made the citation path more than decorative in at least one tested case.

It allowed the user to move from a synthesized claim back to the evidence supporting it.

The evaluation did not manually verify every citation, so the result should not be generalized into “Fabric always cites correctly.”

There was also a second limitation.

The Wave 2 answer correctly identified the USD 4,800 ceiling and grounded it in the approved decision log, but the visible budget CSV was not surfaced among the cited sources.

So the answer could be correct while the displayed source set remained incomplete.

Citation presence increased inspectability.

It did not establish citation completeness.

Free Value Exists, but Capture Remains Manual

The Free plan successfully accepted all 23 approved files used across P01 and P02 through manual batch upload.

That is enough to demonstrate a usable Free workflow for a deliberately maintained small project library.

It is not the same thing as ambient knowledge capture.

Desktop file sync remained Pro-gated in the tested account.

That creates a clear operational boundary around the value demonstrated here.

Fabric Free can become useful after the user creates and maintains the library.

It did not demonstrate the ability to quietly absorb an existing local filesystem and turn it into project memory without that maintenance step.

Manual curation may help some users keep irrelevant material out, but that benefit was not tested here.

For others, especially anyone attracted by the promise of effortless personal memory, the ingestion cost may outweigh the downstream synthesis value.

Implications

Fabric’s v3 result was materially more positive than the earlier Downloads test, but the two findings should not be collapsed.

The first job failed because the natural automatic-ingestion path was unavailable on Free.

The second job succeeded because, once a small mixed-format project library had been intentionally created, Assistant could reconcile changing evidence into a source-linked current state.

That makes Fabric more credible as project memory than as an automatic file organizer, at least under the tested Free conditions.

The strongest product-specific behavior was not generic storage, a generic chatbot answer, or semantic Search by itself.

It was the combination of mixed-format spaces, accumulated project context, chronology handling, contradiction resolution, active-issue preservation, and inspectable source recovery.

That value is also conditional.

A user must have enough file-based project history for reconstruction to be painful, but not so much that the untested scaling limits become the dominant question.

They must also be willing to maintain the library manually on Free.

For users outside that operating pattern, the product may solve a problem they do not have.

Evaluation Limits

P01 and P02 were controlled simulated-persona evaluations using fictional corpora, not recruited-user research or production use.

The P01 library contained 15 files, and the P02 library contained eight files across two upload waves. The strong Assistant results therefore establish bounded capability in small deliberately constructed libraries, not general accuracy at scale.

Plain Search produced both a strong visual-memory result and several incomplete or misleading retrievals. No claim is made that Search is universally unreliable.

Assistant correctly reconciled the controlled chronology and decisions used in the test. This does not establish that it always chooses the correct authority, never hallucinates, or remains reliable over long-running real projects.

One PDF page-specific source path was manually opened and verified. Not every citation was inspected.

The Wave 2 source list did not surface every visible corroborating source, so citation completeness was not demonstrated.

Manual batch upload worked for the tested formats and 23 files. Maximum library size, usage ceilings, larger batch behavior, OCR over real scans, audio, video, DOCX, native spreadsheet workflows, collaboration, sharing, and long-term drift were not tested.

Desktop file sync was Pro-gated in the tested account. No paid plan was activated, and no claim is made that Pro would improve Search accuracy.

The earlier user judgment that Free had no value for the Downloads-organizer job remains scoped to that job. The later v3 result does not invalidate it.

No claim is made that Fabric is a better general-purpose knowledge system than Drive, Notion, ChatGPT, or another file or project-management product. No matched competitor evaluation was conducted.

Conclusion

No claim is made that Fabric solves ambient knowledge capture, that Pro would fix the observed Search inconsistencies, or that Fabric outperforms other project-knowledge tools.

Within the boundaries tested, Fabric failed at the job it first promised — absorbing an existing messy folder automatically — and succeeded at a narrower one: reconciling a deliberately maintained project library into a current, source-linked state. Those are different products for different users, and this evaluation only recommends the second one.

Finding the gap is only half the work. The other half is deciding what to do about it.
