Diagnosis & Priority

Attio: The Agents Finished. The CRM Didn't.

Product Value Evaluation #015 · Published September 2026

Attio's most interesting promise is not that AI can research prospects.

Plenty of tools can do that.

The more distinctive proposition is that CRM context can become the starting point for research, qualification, and reusable human-reviewed action without forcing the user to move repeatedly between a CRM, browser research, separate AI tools, and manual data entry.

This Product Value Evaluation tested that proposition with a nuanced revenue-research task.

The fixed first-use task began with five preselected company records. The simulated user was the founder of a small specialist B2B consultancy with no dedicated sales team. The goal was not autonomous outreach. It was to research public evidence, distinguish genuinely promising prospects from merely relevant companies, and leave the final decision with a human.

The expected value path was:

Company record → Web Agent research → Custom Agent qualification → persistent CRM state → human review

Attio made that architecture visible.

It also exposed where AI-assisted workflow construction can fail even when the underlying product capability works.

The natural-language builder created a reusable workflow combining a record trigger, Web Agent research, and Custom Agent qualification. The eventual research produced differentiated outcomes rather than forcing every company into a positive category.

But the builder stopped one block too early.

The requested qualification results were never written into the CRM because the generated workflow omitted Attio's native Create note step. Five runs completed and consumed 554 credits while every Company record still showed zero notes.

A controlled minimum test reproduced the same builder omission once. The workflow contained only a read-only Custom Agent, the editor reported no error or warning, the run was marked Completed, and no note was created.

Then the product failed a second test.

When asked directly whether that incomplete workflow would persist its result, Ask Attio answered yes and described read-only Notes access as if it could create a permanent note.

Finally, the workflow was manually corrected:

Record action → Custom Agent → Create note

That run completed for two credits and created the expected note on the synthetic Company record.

The underlying write capability worked.

The failure was in how the AI assembled, validated, described, and diagnosed the workflow around it.

Key Findings

  • Attio exposed a genuinely product-specific value architecture: CRM records could provide context, Web Agent could perform external research, and Custom Agent could apply a nuanced user-supplied qualification rubric while leaving final prospect judgment to a human.
  • The AI builder omitted the documented persistence step. It produced research and qualification blocks but not the native Create note block required to turn agent output into durable CRM state — and the omission survived both editor validation and a controlled minimum-test reproduction.
  • Asked directly whether the incomplete workflow would persist its result, Ask Attio incorrectly said yes, describing read-only agent access as if it were permanent write capability.
  • The native write path itself worked. Once Create note was manually added and mapped correctly, the expected Company note was created for two credits.
  • A separate Cursor record showed why CRM identity matters before expensive research: automatic enrichment attached the record to an apparently different company, though the research agents themselves stayed correctly focused on the intended product.
  • The economics were material. Five research-and-qualification runs consumed 554 credits — more than twice the 250-credit monthly Free allowance — though the live workspace was on a Pro trial, so permanent Free-plan viability was not tested.

The Value Architecture Was Real

The first-use experience did something important before it produced any result.

It made Attio's intended division of labor understandable.

The user supplied the qualification logic in natural language rather than manually encoding a conventional sales score.

Attio translated that request into a workflow connecting CRM records, web research, and AI judgment.

The builder did not complete the workflow quickly. It used 19 tools and repeatedly corrected itself before producing the final structure.

But the structure itself was legible.

For the simulated consultancy, that mattered.

The alternative workflow was familiar: maintain a company list somewhere, research each prospect separately, move findings into another AI tool, interpret them manually, and then copy the useful result back into the working system.

Attio suggested a more integrated possibility.

Research could begin from the CRM record itself.

The qualification logic could be reused.

The output could, in principle, become persistent CRM state.

And the human could remain responsible for the actual prospect decision.

That was the product-specific value hypothesis.

P01 Saw the Possibility Before Receiving the Outcome

The formal first-use timebox expired before any qualification result became available.

At the frozen stop, all five runs were still pending.

The user therefore did not leave first use with a ranked prospect list, a usable qualification view, or even a single completed decision.

The frozen conclusion at that point was narrower:

The intended AI-native CRM architecture became visible, but task-level value was not reached within first use.

That distinction is important.

The eventual Strong and Ambiguous outcomes were discovered later during audit.

They should not be retroactively treated as part of the first-use experience.

First use discovered how Attio could create value.

First use did not yet deliver usable value from the completed task.

That is one of the clearest findings in this evaluation.

The Research and Qualification Logic Showed Promise

After first use ended, all five runs eventually completed.

Three companies were classified as Strong candidates and two as Ambiguous.

Those classifications are Attio-generated outputs, not verified findings about the companies themselves.

This evaluation does not establish that the tested companies actually have the Product Value Gaps Attio identified, nor that companies classified as Ambiguous should be treated as weaker prospects.

What the outputs do show is how Attio applied the supplied rubric.

The agent did not simply interpret international presence as evidence of a market problem.

For one AI coding tool in the set, it found stronger expansion signals outside Japan but insufficient Japan-specific evidence, and kept the qualification at Ambiguous.

For another developer-tools company, it similarly identified broader friction without enough Japan-specific mismatch evidence to support a stronger classification.

That restraint was useful.

The product demonstrated that a specialist qualification rule could survive contact with real research without collapsing into generic lead scoring.

The Workflow Stopped One Block Too Early

The central failure appeared after the reasoning was complete.

The workflow builder had been asked to leave the result in the CRM.

Because the originally requested custom attributes did not exist, the builder chose a structured note as the fallback.

But the generated chain ended with the Custom Agent.

Attio's documented architecture makes Custom Agent tools read-only. Agent output is not automatically saved as CRM state. Persistence requires a later native action such as Create note.

That action existed in the live workflow catalog.

The AI builder simply did not add it.

The result was a peculiar state.

All five runs displayed Completed.

The qualification text existed inside individual execution logs.

But every Company record still showed zero notes, and the global Notes collection remained empty.

For the user, that difference is fundamental.

A result hidden inside an execution log is not equivalent to CRM state.

It cannot easily become a sortable prospect view, a filterable qualification list, or a durable next-action record.

The research happened.

The judgment happened.

The operational state did not.

“Completed” Described Execution, Not the Requested Outcome

Attio's status model made the failure harder to detect.

The Custom Agent block ran.

It returned text.

From the runtime's perspective, Completed may therefore have been accurate.

But the task requested more than a completed inference.

It requested a persisted CRM outcome.

No note existed.

This reveals a distinction that matters for agentic software:

block execution is not the same as workflow success, and neither is necessarily the same as business-outcome success.

For this task, a more useful status would have been something like:

Research completed → Qualification completed → Persistence missing

or

Partial success: output generated, CRM write not configured

Instead, the user received a green completion state around an incomplete business result.

A Minimum Test Reproduced the Builder Omission

Because the missing notes were initially discovered in a relatively complex five-company workflow, a smaller controlled test was needed.

A new synthetic Company was created.

No Web Agent research was used.

The prompt requested a fixed note.

The AI builder again produced a workflow containing only a read-only Custom Agent.

It again omitted Create note.

The editor displayed no errors or warnings.

The single run completed in three seconds, consumed one credit, and was marked Completed.

No note was created.

This does not establish that the builder always makes this mistake.

It was reproduced once, in one account, with one controlled prompt.

But it removed one important ambiguity.

The original omission did not depend on Web Agent complexity, the five-company research task, or the particular qualification rubric.

The builder could independently produce the same incomplete persistence chain in a minimal case.

Ask Attio Could Not Diagnose Its Own Workflow

The next test examined a possible recovery path.

A user who suspects something is wrong does not necessarily open external documentation.

Attio already provides an in-product AI surface: Ask Attio.

The incomplete minimum workflow was therefore inspected by asking a direct question:

Does this workflow persist the result?

Ask Attio answered yes.

It described the Custom Agent's Notes tool access as if that read-only access could create a permanent note.

That answer contradicted both the actual workflow structure and Attio's documented capability model.

The missing Create note block was not identified.

This matters because Ask Attio is the natural place for a user to recover from an AI-generated configuration problem.

The same product had enough context to see the workflow graph.

It also had a documented native persistence mechanism.

Yet when asked directly whether persistence existed, it gave false reassurance.

The problem therefore extended beyond initial composition.

The system also failed to accurately inspect its own generated workflow when the user explicitly asked it to do so.

The Corrected Workflow Worked

The final controlled test separated AI composition from native capability.

The workflow was manually repaired to:

Record action → Custom Agent → Create note

The output of the Custom Agent was mapped into the native note-creation block.

The corrected run completed for two credits.

The expected note title and body appeared on the synthetic Company record.

This is an important correction to the interpretation of the earlier failure.

Attio's note-writing capability was not shown to be broken.

In this account, the native write path worked when configured correctly.

The observed failure was concentrated elsewhere:

  • the AI builder omitted a required persistence block;
  • the editor did not flag the missing business outcome;
  • the runtime displayed Completed;
  • Ask Attio incorrectly said persistence was already configured.

The product had the capability.

The AI-assisted path did not reliably assemble or verify it.

Cursor Showed Why Correct Research Is Not Enough

A separate issue appeared in the Cursor record.

Only the company name and cursor.com domain had been supplied.

Attio's automatic enrichment populated the CRM record with details belonging to an apparently different company.

The research agents, however, were investigating the intended current AI coding product.

Their output referred to current product and market conditions.

The Custom Agent also noticed the identity mismatch and warned that the CRM record likely did not represent the intended prospect.

That identity warning was separate from the Ambiguous qualification.

The Ambiguous result was driven primarily by insufficient Japan-specific evidence, not by the identity conflict itself.

Still, the conflict matters.

The system reached a state in which the research layer was reasoning about one company while the CRM master represented another.

This is a particularly important risk in an AI-native CRM.

Research, scoring, routing, and future action inherit the identity of the underlying record.

If that identity is wrong, individually sensible AI outputs can still become operationally misplaced.

In this case, the agent itself was capable of noticing the mismatch.

The opportunity is to surface that uncertainty earlier, before a credit-consuming research workflow runs.

The Credit Cost Was Not Trivial

The five-company workflow consumed 554 credits, with individual runs ranging from 97 to 124 credits.

The frozen public baseline listed 250 workspace credits per month on the Free plan.

The live workspace was operating under an automatic 14-day Pro trial, so this evaluation does not establish permanent Free-plan behavior or exact plan equivalence.

It does establish that the observed five-company workflow consumed more than twice the frozen Free monthly allowance.

That makes credit visibility part of the product-value equation.

For a small team, the question is not only: can this workflow work?

It is also: how much will a reusable version cost every time it runs?

The Cursor case makes that particularly concrete. One 97-credit run proceeded despite an unresolved company-identity problem.

A pre-run estimate of likely credits and runtime would help users decide whether the workflow is proportionate to the value of the decision being made.

Japan Was a Qualification Dimension, Not the Product Problem

This evaluation targeted a Japan-sensitive use case.

That did not produce evidence of a broad Japan localization problem in Attio itself.

The more interesting result was that the workflow could encode a qualification rule in which Japan presence alone was insufficient.

The agent could distinguish between generic international signals and evidence specifically relevant to Japan, and it could leave a company at Ambiguous when that evidence was insufficient.

The Product Value Gap observed here was therefore not primarily linguistic or cultural.

It was operational.

Nuanced market-specific judgment only creates usable value when:

  • the right company identity is attached to the record;
  • the research arrives in a useful timeframe;
  • the credit cost is understandable;
  • the result becomes durable CRM state;
  • and the human reviewer can see the outcome without opening individual execution logs.

Those requirements matter in Japan.

They are not unique to Japan.

What Attio Could Improve

Three improvements stand out because each depends on capabilities Attio already has.

1. Make the AI builder complete the requested persistence chain. If a user asks for research, qualification, and storage, the builder should generate the complete chain required to produce that durable state. For this use case, agent output → Create note should have been generated automatically. Attio can also validate the graph before publication: if the user's requested outcome is to save a note and no persistence block exists, the workflow should not pass silently. The correct native Create note block already exists — the observed gap was specifically between Attio's natural-language builder and Attio's own workflow capability model.

2. Make completion reflect the requested business outcome. A successful model invocation should not automatically imply a successful workflow outcome. Attio can inspect its own CRM state after execution. If the expected note, attribute update, list assignment, or other mutation did not occur, the run can report partial success rather than simply Completed. Only Attio can reconcile agent execution with the resulting state of Attio's own CRM.

3. Make Ask Attio inspect the actual workflow before answering capability questions. Ask Attio is the natural recovery surface for users who do not want to leave the product and read documentation. When asked whether a workflow persists output, it should inspect the actual block graph and tool permissions before answering. In this case, the useful response would have been: “The Custom Agent is read-only. This workflow does not currently persist the result. Add Create note after the agent.” Ideally, it could then offer to make the repair. Ask Attio has contextual access to the workflow the user is already building, which uniquely positions it to connect explanation, diagnosis, and repair.

A fourth opportunity is worth monitoring rather than elevating to the core finding: when automatic enrichment conflicts with the supplied domain or current web identity, Attio could insert an entity-confirmation gate before expensive Agent research begins.

Product Value Assessment

Attio demonstrated more value than a generic “AI inside CRM” story.

The combination of Company records, Web Agent research, Custom Agent qualification, reusable workflows, and human review maps well to a real specialist research problem.

That architecture was discoverable.

The eventual agent outputs also showed enough differentiation to suggest that the supplied qualification logic was doing meaningful work rather than producing generic positive scores.

But the operational value did not reach the user during first use.

The initial workflow took time to construct.

The first-use window ended before results arrived.

When those results eventually appeared, they remained trapped in execution logs because the AI-generated workflow had stopped before the persistence step.

A minimum reproduction showed the same omission once.

Ask Attio then incorrectly assured the user that the incomplete workflow already persisted its output.

Only after manual repair did the intended closed loop work.

That final success is important.

It changes the conclusion from Attio could not do the task to Attio could do the task, but its AI-assisted construction path did not reliably assemble or verify the complete workflow required to deliver the value.

That is a much more specific finding.

For users, the practical lesson is equally specific.

When building a consequential Attio workflow with AI, do not verify only what the Agent researches or concludes.

Verify the last operational step: where does this result actually go?

For Attio, the opportunity is to make that verification unnecessary more often.

The product already contains the research layer, the reasoning layer, and the native persistence primitive.

The missing value was in connecting them reliably.

The agents finished.

The CRM didn't.

Until the final block was added.

Evaluation Limits

This evaluation used one approved simulated persona, not a recruited participant.

The fixed seed set consisted of five companies, identified only by name and domain. No prior evaluator findings were provided to Attio.

The formal first-use timebox expired before qualification results became available. Later findings from the persona-free audit were not imported back into the frozen first-use reaction.

The workspace entered an automatic 14-day Pro trial. Permanent Free-plan behavior was not tested, and no payment-method request was observed.

The public research produced by Attio about the five companies was not independently fact-checked during the bounded audit. Strong and Ambiguous labels should therefore be interpreted as product outputs rather than verified assessments of those companies.

The AI builder's omission of Create note was reproduced once with a separate controlled minimum prompt. That single reproduction does not establish a frequency across prompts, accounts, models, or future product versions.

Ask Attio was tested once with one direct persistence question. This evaluation does not establish its broader diagnostic accuracy.

The manually corrected Create note chain was executed once and succeeded. Broader reliability of the native write path was not measured.

The Cursor CRM record showed one observed entity mismatch. No general entity-resolution error rate should be inferred.

No outreach was drafted or sent. No email or calendar account was connected.

The evaluation therefore supports a narrow conclusion about one research-and-qualification workflow and the AI-assisted path used to construct it, not a general reliability claim about Attio as a whole.

Finding the gap is only half the work. The other half is deciding what to do about it.
